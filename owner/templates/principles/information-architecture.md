# 信息组织指南

本指南是 owner skill 「信息架构优先」原则的实践展开。

信息组织对人类很重要，也会反过来提升 AI 的执行质量。文档不是越全越好，而是要让人快速建立正确心智。

## 基本原则

- 一块内容只讲一个内聚主题。
- 每块文字尽量短，信息密度要高。
- 粗粒度原则和细粒度实践分开写。
- 入口文件负责导航和关键约束，细节文件负责展开。
- 当一段内容开始承载多个主题、多个层级或过长细则时，就要拆。
- 内容先粗后细：先给读者地图，再给细节。
- 条目先分组再罗列：不要把不同能力、不同层级、不同状态摊平成一长串。

## SKILL.md 的职责

`SKILL.md` 是 skill 入口和总章程，主要放：

- 角色定位。
- 核心原则。
- 路由。
- 启动纪律。
- 常用实践的高密度摘要和链接。

不要把大量操作细则、例外情况、长 checklist 全塞进 `SKILL.md`。这些内容应该放进对应 skill 的子文件或 `guides/`。

## 拆分判断

出现以下信号时，优先拆文件：

- 一个章节超过几屏，且不是所有路径都会读。
- 同一章节同时讲原则、流程、模板和例外。
- 人类读者需要滚很久才能找到下一条同级信息。
- 后续维护时只想改一个实践，却必须在总入口里翻找。

拆分后，入口保留一句话摘要和链接；细节文件保持内聚，不要为了拆而把强相关信息打散。

## Roadmap / Task / 交付物组织

Roadmap、task、交付报告都要照顾人类阅读。读者应该先看到"现在整体是什么样"，再进入细节。

### Roadmap

Roadmap 的当前状态不要写成一串干条目。推荐结构：

1. 阶段一句话：当前处在哪个阶段，目标是什么。
2. 能力分组：按产品/工程/验证/风险，或按子系统，把已有能力和缺口分组。
3. 每组先写总结，再列细项。
4. 细项只保留对下一步决策有价值的内容；流水账进 task 或历史记录。

错误信号：

- "当前状态"下面几十个 bullet 全是同级功能点。
- 读者必须读完整段才能知道系统大概做到哪。
- 已完成、进行中、风险、验证混在一起。
- 旧细节长期占据 active Roadmap，让当前阶段不突出。

### Task

task 是执行文档，不是聊天日志。推荐结构：

1. 目标和范围先讲清楚。
2. 执行记录按时间排，但每条要有信息价值。
3. 发现的问题按"已处理 / 待处理 / 需老板拍板"分组。
4. 验证证据集中放，不要散落在流水记录里让人找。

### 交付物

交付物面向判断。推荐结构：

1. 先给结论。
2. 再给证据。
3. 再给细节。
4. 最后给风险、后续建议和未决问题。

如果一个文档读起来像"把所有发生过的事按时间倒出来"，说明它还没有经过信息组织。
