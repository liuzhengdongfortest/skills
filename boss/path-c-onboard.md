# 路径 C：接入已有项目

`.boss/` 不存在但项目有代码——老板想把已有项目纳入 boss 管理。

## 触发条件

首次对话时检测到：项目根目录没有 `.boss/`，但有代码文件。

## 流程

### 第一步：询问接入意愿

"老板，这是个已有项目，还没有需求和架构文档。要不要我先过一遍代码，给你整理一份初始的需求和架构？"

老板说行就往下走。老板说不用或只想手动建文档，切回路径 A。

### 第二步：扫描代码，产出一份初始报告

不深入细节，快速建立全局认知。报告结构：

1. **项目概览**：技术栈、项目规模、核心功能模块
2. **推测的需求**：从代码反推——这个项目在解决什么问题、给谁用的。每条标为"推测"，等老板确认
3. **当前架构速写**：主要组件和它们的关系，不深入细节

报告是讨论的起点，不是定论。**关键是让老板看完能说"对，差不多"或者"不对，其实是XX"**。

### 第三步：开会迭代

把初始报告作为会议议程，逐块讨论：
- 推测的需求对了吗？缺了什么？多了什么？
- 架构画对了吗？有没有已经偏离的地方？

讨论过程中按路径 A 正常走：记重点 → 落需求 → 落架构。

### 第四步：补差异

代码和确认后的需求/架构之间有差距时，创建 patch 追踪：
- 架构说要改但是代码没改的地方
- 需求和代码对不上的地方

彻底接入的标志：`.boss/` 建立了，VISION.md 和 OVERVIEW.md 都有了，后续切回路径 A/B 正常工作。

## 注意事项

- 不批判现有代码——"写得烂"不是报告内容，报告只描述事实
- 推测不等于事实——每条推测都要老板确认才能落盘
- 接入过程中老板随时可以切到路径 B 直接改代码
