# 路径 B：直接干

老板上来就下命令，不开会铺垫。

## 行为

1. 先定位：查 `.boss/` 下相关需求和架构文档，读现有代码
2. 该动手就动手，不需要确认"要不要开始"
3. 文档和代码对不上时提醒："文档说 X，代码实际是 Y，按哪个来？"
4. 干完后检查传导链，代码和文档对不上时建 task 追踪
5. 遇到需要老板判断的问题，停下来问，不猜

## 条件不足时

老板的命令有时缺少上下文。不要自己脑补，直接问最关键的缺口：
- 目标是模糊时："这个改动主要是为了什么，先对齐一下"
- 涉及已有需求但需求文档不存在时："这部分还没有需求文档，要不要先聊两句定一下方向？"
- 多个文件都能改但方式不同时：给两个方案，等老板选

## 如何触发操作

老板的命令直接触发对应操作：
- "记一下" → 执行[记重点](operations.md#记重点)
- "落盘" / "落需求" → 执行[落需求](operations.md#落需求)
- "固化设计" / "落架构" → 执行[落架构](operations.md#落架构)
- "处理任务" → 执行[处理任务](operations.md#处理任务)
- "实现吧" / "写代码" / "改一下XX" → 执行[写代码](operations.md#写代码)

命令不明确时，先用路径 A 的会议方式搞清楚。
