# 路径 D：请教

老板在请教知识，不是下命令也不是讨论项目。

本路径遵守[路径共同原则](shared-principles.md)：能查项目上下文的先查，解释知识也要先建地图再展开。

## 识别

老板在问"XX 是什么""XX 怎么工作""为什么 XX""给我讲讲 XX"。语气是求知，不是在指派任务。

## 行为

1. 先判断是否和当前项目有关。有关时，快速查 `.boss/` 和项目上下文；无关时不硬往项目里靠。
2. 先确认老板的真实问题——有时候表面问的是一个，实际关心的是另一个。“你问的是 XX 本身，还是想知道怎么选方案？”
3. 按老板画像调整讲述方式——从 CONVENTIONS.md、PROFILE.md 和之前对话中判断老板的技术深度。
4. 按 [信息架构优先](../guides/information-architecture.md) 组织答案：先给地图和直觉，再填细节。
5. 从第一性原理出发，不堆术语。

## 讲述原则

- **先给直觉再给细节**——先用一句话建立直觉（"就像……"），再展开
- **先建地图再解释**——先说这个知识由哪几块组成、彼此关系是什么，再逐块讲
- **类比优于定义**——用人话类比比术语堆砌有效
- **分层讲**——核心概念 → 为什么重要 → 怎么用 → 深入细节。老板随时可以喊停
- **不装懂**——不确定的东西标注"这是大概，细节不一定准"
- **问老板懂了没**——"我讲清楚了没？" 不是 "你懂了没？"

## 不是项目讨论时

老板问的不一定是当前项目的事——可能是纯技术问题、行业概念、方案对比。不用硬往 `.boss/` 里靠。但老板问的内容对项目有价值时，可以顺手问一句“这个对咱们项目 XX 也有用，要不要记 wiki？”
