# 术语指南

日常语言里的"计划"容易混淆。客户说"列个计划"，不一定是在要求创建 `.boss/roadmaps/`。

## Roadmap / 路线图

Roadmap 是长期目标的控制面板，对应 `.boss/roadmaps/` 下的文档。

它回答：

- 长期目标是什么。
- 分几个阶段走。
- 当前阶段在哪里。
- 当前阶段有哪些 planned 条目。
- 哪些条目已经升级为 task。
- 当前状态、风险和完成标准是什么。

触发信号：

- 长期目标。
- 阶段推进。
- 多轮执行。
- "按计划推进""持续执行""做到阶段 X 再汇报"。
- 需要把一组任务放进同一个控制面板。

## Task 执行方案

执行方案是 task 文档里的局部方案，不对应 `.boss/roadmaps/`。

它回答：

- 这个 task 准备怎么做。
- 先改哪里，后改哪里。
- 验证怎么跑。
- 风险和回退点是什么。

触发信号：

- "先列个计划给我看"但上下文是一个具体改动。
- "这个任务怎么做"。
- "实现前说一下步骤"。
- "给我一个改法/方案"。

## 判断规则

- 如果目标跨阶段、跨多轮、需要维护状态地图 → 创建或更新 Roadmap。
- 如果目标小、范围有界、可独立验证 → 直接创建/执行 task，不需要 Roadmap。"小"指不需要阶段地图和长期状态面板，不指原子操作；一个 task 可以包含多个关联步骤、多个 commit、跨多轮会话。
- Roadmap 可以引用 task；Roadmap 派生的 task 可以保留可选 `roadmap` 回链，但 task 的叙述保持独立。
- 如果只是一个 task 的实施步骤 → 写进 task 的执行方案，不创建 `.boss/roadmaps/`。
- 如果客户只说"计划"，先看上下文；能从上下文判断就不要问。
- 如果两者都可能且影响文档结构，问一句："这是要长期路线图，还是这个 task 的执行方案？"
